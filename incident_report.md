# Cybersecurity Incident Response Simulation Report

## 1. Introduction
Incident response is the process of identifying, analysing, managing, and recovering from cybersecurity incidents. This project demonstrates how an organisation can respond to a simulated cyberattack.

## 2. Incident Scenario
An employee receives a phishing email that appears to contain an important document. The email includes a fake document-sharing link. The employee clicks the link, enters their login credentials, and approves an unexpected multi-factor authentication request.

An attacker then gains unauthorised access to the employee's account. The security team notices an unusual login, an unauthorised email forwarding rule, and unexpected file modifications. Possible ransomware activity is suspected, but it has not yet been confirmed.

## 3. Type of Attack
- Phishing attack
- Account compromise
- Suspected ransomware activity

## 4. Affected Systems
- Employee email account
- Shared file server
- Organisational network

## 5. Detection and Analysis
The security team identifies unusual login activity and suspicious mailbox changes. The team investigates the affected account, checks system logs, and determines the possible scope of the incident.

## 6. Containment
- Disable or temporarily restrict the compromised account.
- Revoke active login sessions.
- Block suspicious links and senders.
- Isolate affected devices from the network if necessary.
- Preserve relevant logs and evidence.

## 7. Eradication
- Remove unauthorised mailbox forwarding rules.
- Reset compromised passwords.
- Review and remove unauthorised access.
- Scan affected systems for malicious activity.
- Fix the security weaknesses that allowed the incident.

## 8. Recovery
- Restore affected files from verified backups.
- Reconnect systems after security checks.
- Monitor accounts and network activity.
- Confirm that normal operations have resumed.

## 9. Impact and Risk Assessment
The incident could affect:
- Confidentiality: Unauthorised access to employee or organisational information.
- Integrity: Unauthorised changes to files and email settings.
- Availability: Possible disruption to shared files and business operations.

## 10. Lessons Learned
- Employees should be trained to identify phishing emails.
- Unexpected MFA requests should never be approved.
- Security logs should be monitored regularly.
- Backups should be maintained and tested.
- Incidents should be reported immediately.

## 11. Recommendations
1. Enable multi-factor authentication.
2. Conduct regular cybersecurity awareness training.
3. Use endpoint protection and email filtering.
4. Maintain secure and tested backups.
5. Monitor unusual account activity.
6. Prepare and regularly test an incident response plan.

## 12. Conclusion
This simulation demonstrates how a structured incident response process helps organisations manage cybersecurity incidents. Early detection, quick containment, proper eradication, and secure recovery can reduce damage and improve overall security.

**Note:** This is a fictional educational tabletop simulation. No real organisation, account, or computer system was involved.
